# Sunfall Arc Context

## Domain Vocabulary

- **Runtime Spine**: the `SunfallArcRuntime<R, ER>` that owns Effect execution for an app, browser session, server request, or test. It carries the Effect `ManagedRuntime`, the Resource Store, and the services that app work depends on; its typed Interface only discharges services actually provided by `R`.
- **Erased Runtime Runner**: the `AnySunfallArcRuntime<ER>` Adapter Interface used at Solid contexts, platform adapters, and ambient host seams where the concrete app service set cannot be named. It is explicit erasure, not a replacement for typed Runtime Spine APIs.
- **Request Runtime**: a per-request view of the app Runtime Spine with the same Effect services and a fresh Resource Store. Start uses it for SSR preload, render, and server RPC work.
- **Request Runtime Lifecycle Module**: the internal Start Module in `packages/start/src/request-runtime-lifecycle.ts` that runs a selected response Effect through response-context application, Request Runtime disposal, request trace emission, failure/interruption teardown, and streamed response finalization. The Start Request Handler owns endpoint/render selection; this Module owns lifecycle completion.
- **Resource Definition**: the stable `Resource.family(...)` descriptor. It names the resource, describes input/output/error schemas or types, and defines loading policy, but does not own live cache state.
- **Resource Store**: the runtime/request-scoped owner of live resource entries, Effect caches, known resource inputs, semantic tag index, hydration state, and resource lifetime fibers. This is the seam that keeps SSR requests, client runtimes, and tests isolated. Its public Interface exposes event bus, module registry, fiber registry, and diagnostics Modules; raw entry/input/cache maps remain internal implementation state.
- **Resource Runtime**: the Core Module that binds Resource Definitions to the active Resource Store. It owns runtime store lookup, touched-ref collection, in-flight fiber coordination, synchronous read state, invalidation execution, dehydration, and hydration behind the public Resource facade.
- **Resource Read Boundary**: the synchronous Core read Interface for already-loaded Resource refs. Missing or expired data throws typed `ResourcePending` and failed data throws `ResourceFailure`; UI adapters such as Solid and React own any host Suspense conversion they need to throw.
- **Resource Read Decision**: the Core Resource Runtime policy that computes one read outcome for sync `Resource.read(...)` and Effect `Resource.readEffect(...)`: value, typed pending, typed failure, collected reset, and stale refresh. Sync and Effect callers adapt that decision instead of duplicating Resource Read Boundary rules.
- **Resource UI Binding Controller**: the Core Module in `packages/core/src/resource-ui-binding.ts` that owns adapter-neutral Resource UI policy: ref identity, runtime-bound refresh/prefetch Effects, automatic preload fibers, keyed preload failures, observer and host setter failure swallowing, stale preload interruption, retained-ref cleanup through `disposeEffect()`, and Suspense preload-token dedupe. It consumes Resource Runtime functions directly instead of routing sibling implementation work through the public `Resource` facade. React and Solid keep host reactivity and host Suspense throwing at their adapter seams.
- **Resource Suspense Preload Controller**: the Core Module in `packages/core/src/resource-ui-binding.ts` that dedupes host Suspense tokens per Resource ref, owns preload join fibers, observer removal, stale-ref interruption, and exposes `interruptEffect()`/`disposeEffect()` so adapters can await cleanup while keeping sync host cleanup conveniences.
- **Collection Definition**: the stable `Collection.define(...)` descriptor. It names a keyed row set, describes loading and mutation handlers, and exposes typed collection operations, but should not own live row state directly.
- **Collection Store**: the runtime/request-scoped owner of collection rows, load state, pending mutation queues, and collection event streams. It follows the same isolation rule as the Resource Store: SSR requests, client runtimes, and tests must not share live collection state.
- **Runtime Collection Store**: the DB Module that resolves and initializes the active Collection Store through the Runtime Spine's Resource Store module registry. It owns store creation, initial row materialization, diagnostics snapshots, event subscriptions, and synchronous `runWithCollectionStore(...)` override locality.
- **Collection Runtime**: the DB Module that binds a Collection Definition to the active Runtime Collection Store. It owns load/refetch, optimistic mutation execution, pending flush replay, write/change routing, hydration, persistence coordination, and collection event publication behind the public Collection facade.
- **Collection Value Detachment**: the DB Module that owns deep value cloning, frozen transaction/value copies, update-draft detachment, mutation/transaction cloning, and public row DTO detachment before collection values cross store, snapshot, live-query, mutation, or adapter seams.
- **Collection Projection Callback Policy**: the internal DB Module in `packages/db/src/collection-projection-callback-policy.ts` that owns pure row projection callback invocation, active Collection Store state lookup normalization, functional `CollectionUpdate` application, and row-key preservation. Effect APIs report projection and state lookup throws as `EffectInputCallbackError`, key-changing updates as `CollectionRowKeyChanged`, and sync read interfaces remain synchronous.
- **Collection Secondary Index**: a named, Collection Definition-owned selector that the active Collection Store materializes into runtime/request-local lookup buckets. It supports scalar and multi-value index selectors while preserving runtime/request locality.
- **Collection Index Materialization**: the DB Module that owns secondary-index normalization, lookup-key encoding, duplicate-value dedupe, runtime/request-local bucket caches, index-row reads, indexed join keys, and the public `UnknownCollectionIndex` error.
- **Collection Event Stream**: the Collection Store's Effect `PubSub` of collection lifecycle and mutation facts, used by tests, devtools, and future sync adapters without exposing private row maps.
- **Collection Preload Collector**: the `@sunfall/arc-db` Effect service installed by `Collection.collectEffect(...)`. It records Collection Definitions whose `preloadEffect` or `refetchEffect` runs during route preload without requiring `@sunfall/arc-core` to import DB.
- **Collection Hydration Payload**: the serializable DB snapshot for one or more Collection Definitions. It contains rows, row metadata, pending optimistic mutation facts, and rollback rows needed to restore request or browser collection state.
- **Collection Mutation Queue**: the runtime/request-scoped list of in-flight optimistic collection transactions. It records active attempts, transaction retries, and rollback rows so persistence, devtools, and future sync adapters can observe or join pending local work without replaying a handler that is already in flight.
- **Collection Mutation Workflow**: the internal DB Module in `packages/db/src/collection-mutation-workflow.ts` that owns optimistic insert/update/delete transaction construction, mutation handler DTO detachment, `Deferred` active-attempt joiners, `Schedule` retry, commit/rollback, lifecycle events, mutation persistence, and restored pending-flush replay. Collection Runtime delegates to it so row reads, direct writes, change-feed application, hydration, and persistence facades stay separate from queued mutation execution.
- **Collection Policy Module**: the internal DB Module in `packages/db/src/collection-policy.ts` that applies Collection Definition execution policy such as `policy.retry` to load and mutation Effects. Collection Sync Load Policy and Collection Mutation Workflow consume this Module so retry semantics have one implementation Seam.
- **Collection Transaction Identity**: the Collection Store-local counter for optimistic mutation transaction ids. Hydration advances it from restored pending mutations so new local writes cannot collide with restored transaction facts.
- **Collection Change Batch**: a host-neutral list of external row upserts and deletes applied through the Collection Store. It lets change-feed adapters update rows, metadata, secondary indexes, persistence, and live queries without accessing private row maps.
- **Collection Write Commit**: the DB Module that owns direct-write atomicity. It snapshots Collection Store state, applies direct row changes supplied by Collection Runtime, persists the resulting snapshot, restores on persistence failure, and publishes one `CollectionWritten` event only after the commit succeeds.
- **Collection Change Feed Adapter**: a scoped Adapter that subscribes to an external row-change source and emits Collection Change Batches through the Collection Store. Electric, PowerSync, websocket, worker, and test feeds should satisfy this seam rather than owning collection row state. Adapters may use the host-callback `emitChanges(...)` helper when the external source cannot run Effects directly; the Collection Change Feed Runtime owns subscription Effect execution and `CollectionChangeFeedFailure` reporting.
- **Collection Change Feed Runtime**: the internal DB Module in `packages/db/src/collection-change-feed-runtime.ts` that runs a scoped Change Feed Adapter against one active Collection Store. It owns dispatcher acquisition, consumer-fiber lifecycle, adapter subscribe/unsubscribe normalization, default write-option application, direct `emit(...)` completion, host `emitChanges(...)` queueing, late-emission drop behavior, and asynchronous failure publication while Collection Runtime owns row mutation policy.
- **Collection Change Feed Dispatcher**: the scoped DB Module that owns change-feed host callback queueing, active/released state, dispatcher shutdown, direct-emission completion, and deterministic late-emission dropping after a subscription scope closes.
- **Collection Mutation Flush**: the Effect-first operation that replays restored pending mutation facts through a Collection Definition's mutation handlers, then commits synced rows or restores rollback rows from the Collection Mutation Queue.
- **Collection Flush Policy**: the Effect-first coordination Module that flushes pending mutations across multiple Collection Definitions and can skip collections while offline, blocked, or otherwise not ready to send.
- **Collection Background Sync Adapter**: a host-supplied Adapter that decides whether a pending Collection Mutation Flush should run for a trigger such as online, visibility, restore, or manual work. It keeps browser, native, and worker scheduling details outside the DB Module.
- **Collection Sync Adapter**: the Adapter Interface that maps an external row source into Collection Definition load, refetch, insert, update, and delete handlers. Server functions, Electric, PowerSync, TanStack Query-shaped sources, and tests should satisfy this seam rather than duplicating mutation plumbing.
- **Collection Sync Load Policy**: the internal DB Module in `packages/db/src/collection-sync-load-policy.ts` that chooses Collection Sync Adapter `load` or `refetch` from the active Collection Store state and `preloadEffect`/`refetchEffect` force flag. It owns Effect v4 in-flight `Deferred` load/refetch generations, restore-before-load, retry, row replacement, lifecycle events, and load persistence so first-load state stays runtime/request-local instead of living in Adapter closure state, concurrent preloads join, and slower old loads cannot overwrite newer forced refetches.
- **Collection Resource Sync Adapter**: a Collection Sync Adapter implementation that uses an Effect Resource ref returning row arrays as the collection load/refetch source while preserving Collection-owned row metadata, mutation queues, indexes, and live queries.
- **Collection Query Sync Adapter**: a Collection Sync Adapter implementation that uses a TanStack Query-shaped client with `fetchQuery` and optional invalidation as the collection load, refetch, and post-mutation cache coordination source.
- **Collection Server Adapter**: a Collection Sync Adapter implementation that adapts Start server functions and Effect callbacks into Collection Definition load and mutation handlers. Host Promise work must be wrapped at the host Adapter seam with `Effect.tryPromise(...)` before it enters Collection handlers.
- **Live Query Collection**: a read-only Collection Definition backed by a `Query.live(...)` graph. It lets derived D2/materialized results participate in collection-shaped APIs without duplicating source row ownership. Collection mutation and change-batch APIs must reject it before row writes, events, or persistence.
- **Live Query Collection Module**: the DB Adapter Module that turns a Live Query graph into a read-only Collection Definition with collection-shaped state, snapshots, indexes, preload collection, and persistence handoff.
- **Live Query Collection Materialization**: the private DB projection Module in `packages/db/src/live-query-collection-materialization.ts` that computes per-Runtime Collection Store keyed rows for a Live Query Collection once and feeds `rows`, `get`, indexes, snapshots, state, `version`, and `Ready.updatedAt` from that same projection.
- **Store-Explicit Collection Snapshot**: the internal DB Interface in `packages/db/src/collection-definition-snapshot.ts` for Collection Definitions whose snapshots must be computed against the supplied Runtime Collection Store rather than the ambient store. The marker, guard, snapshot dispatch, and hydrate preflight dispatch live together so marked definitions cannot silently fall back to ambient snapshots.
- **Indexed Join Plan**: a Query plan step that joins through scalar or multi-value Collection Secondary Index buckets instead of scanning the joined collection for each left-side row.
- **Collection Query Source Adapter**: the internal DB Adapter Module in `packages/db/src/query-source-adapter.ts` that presents Collection Definitions and Live Query Collections to Query Builder, Query Plan, Live Query State, and Live Query Runtime through one query-readable Interface for rows, row counts, secondary indexes, version/state signals, and preload/refetch Effects.
- **Query Stage Plan**: the internal DB Query Module Interface compiled from a fluent Query Builder. It owns source roles, unique source adapters, base-source ordering, identity alias ordering, join sources, grouping, filters, ordering, and window facts so snapshot execution, projection, preload/refetch, Live Query State, and Live Query Runtime share one stage plan instead of re-deciding stage policy separately.
- **Query Execution Plan Module**: the internal DB Module in `packages/db/src/query-execution-plan.ts` that owns Query validation entrypoints, source alias validation, source adapter selection, source preload/refetch, snapshot execution, diagnostics, stable equal-order tie-break identity, and remaining projection stages after live-query IVM has already applied filters, grouping, ordering, or windows. Query Builder stays the immutable DSL while Query once/live/diagnostics callers consume this Module.
- **Query Context Identity**: the internal DB Module in `packages/db/src/query-context-identity.ts` that owns source alias/key identity, merged context identity, ordered-context tie-break identity, IVM context metadata, and collection row delta identity shared by Query Execution Plan and Live Query Runtime.
- **Query Plan Diagnostics**: an inspectable summary of a Query plan's sources, joins, join strategy, row counts, and estimated comparison cost. It gives devtools leverage without exposing Query Builder internals.
- **Query Builder Module**: the DB Module that owns the immutable Query DSL, aggregate helpers, one-shot query facades, live query creation, and query diagnostics facades behind the public DB root facade. The `Query.*` namespace is the preferred public Interface; top-level Query type mirrors remain expert-public compatibility pins and should track the namespace vocabulary.
- **Live Query Runtime**: the DB Module that owns incremental IVM graph construction, source synchronization, joins, grouping, ordering, windowing, and output multiplicity for reactive queries while delegating query-stage projection policy to the Query Execution Plan Module.
- **Live Query State**: the DB Module that adapts Live Query Runtime evaluation into the public `LiveQuery` handle, owning last-good data retention, evaluation failures, and source collection load-state folding. Mutable engine/evaluation facts are keyed by the active Collection Store, not by the Live Query descriptor, so SSR requests, browser runtimes, and tests do not share derived query state.
- **Collection Durable Storage Adapter**: a persistence Adapter that satisfies the collection snapshot storage Interface with a durable driver. The DB Module should keep this seam storage-engine-shaped rather than browser-API-shaped.
- **Collection SQLite Persistence Driver**: the SQLite-shaped durable storage Interface for collection snapshots. It addresses rows by namespace and key, stores schema version metadata, exposes expert-public default table/namespace/schema-version constants, and can be implemented by OPFS SQLite, Node SQLite, React Native SQLite, Durable Objects, or tests.
- **Collection SQLite Statement Adapter**: the dependency-free Adapter that turns a minimal SQL `execute`/`select` driver into a Collection SQLite Persistence Driver. It owns the statement value, params, row, and database contracts; the public DB root aliases those types for namespace ergonomics.
- **Collection SQLite Prepared Statement Adapter**: the dependency-free Adapter that turns prepare/run/all SQLite clients into the Collection SQLite Statement Adapter Interface.
- **Collection SQLite Memory Statement Adapter**: the in-memory reference Adapter for the generated SQLite persistence SQL. It is useful for tests, docs, and host adapter development because it exercises the same statement-driver Interface without a native SQLite dependency.
- **Collection Persistence Policy**: the Collection Definition option that restores a persisted snapshot during preload and persists row plus pending mutation state after loads, writes, and optimistic mutation queue changes. The persistence module owns `persistedCollectionOptions(...)`, which preserves collection handler error/requirement channels while unioning persistence storage channels.
- **Collection Contract**: the DB Module that owns Collection Definition, row, mutation, snapshot, persistence, diagnostics, and store-event contracts. Internal DB Modules depend on this contract instead of the package root facade.
- **Collection Registry**: the DB Module that owns Collection Definition registration, definition lookup, default registry access, isolated registry adapters, deterministic duplicate handling, duplicate diagnostics, and collection diagnostics projection.
- **Collection Snapshot Codec**: the DB Module that validates, clones, encodes, decodes, hydrates, and serializes collection row snapshots plus pending mutation facts before they cross persistence or hydration seams. Invalid persisted JSON fails with a typed `CollectionSnapshotCodecError` in the Effect error channel.
- **Collection Snapshot Interface**: the Collection Definition-owned `snapshot`, `snapshotEffect`, `hydrate`, and `hydrateEffect` Interface used by persistence and hydration callers. Live Query Collections can satisfy this Interface without exposing a writable Collection Store, while normal collections delegate to the Collection Runtime. Snapshot Effects normalize row-projection callback throws such as `getKey` failures into `EffectInputCallbackError` instead of defecting during persistence.
- **Collection Snapshot Persistence**: the DB persistence Module helper that encodes a Collection Snapshot Interface and writes it to Effect-aware storage through `EffectInputCallbackError` normalization. Normal collections add store events around it; Live Query Collections reuse the same storage callback policy without owning a writable store.
- **Collection Hydration Plan**: the DB persistence Module policy that validates a Collection Hydration Payload, resolves Collection Definitions, runs definition-owned preflight, and runs target-store preflight once before either applying hydration or returning successful validation.
- **Resource Snapshot Codec**: the Core Module that validates, clones, encodes, decodes, and applies Resource hydration snapshots before they cross SSR, persistence, or adapter seams. Invalid payloads fail with typed `ResourceSnapshotCodecError` or `ResourceHydrationApplyError` values instead of raw decode failures.
- **Stable Identity Codec**: the Core stable identity Module used by query, live-query, and diagnostic fingerprints. It has structured encodings for JSON-compatible data, Date, URL, Map, Set, binary values, undefined, sparse array holes, marker-shaped plain objects, and typed failures for unsupported values.
- **Resource Lifetime**: the Effect-native lifecycle of a resource entry, including pending refresh interruption, cache invalidation, GC sleep fibers, and deletion.
- **Resource Event Stream**: the Resource Store's Effect `PubSub` of lifecycle facts, used by tests and future devtools to observe resource behavior without reading private maps.
- **Resource Dependency Graph**: the Resource Store's mapping from semantic `Resource.tag(...)` values to the live resource refs that most recently provided those facts.
- **Resource Load Error**: the public Resource error channel for load state,
  status, and preload/refresh Effects. It is the declared load error plus
  `EffectInputCallbackError` from synchronous `load` or `provides` callback
  throws.
- **Signal Dependency Tracker**: the Core Module that records signal dependencies while `watch(...)` callbacks and `Signal.derive(...)` computations run. It owns source de-duping, subscription cleanup, and queued recompute behavior.
- **EffectInput Promise Guard**: the Core Module policy that rejects Promise-shaped values, including union success values with Promise-like members, crossing `EffectInput` seams at the public type surface and at runtime. Host Promise work must be adapted through `Effect.tryPromise(...)`, while internal Action, Resource, Server, Form, Collection, and Start callbacks stay Effect-first.
- **Effect-first Source Audit**: the workspace verification script that scans package source, workspace scripts, public type tests, generated starter templates, and copyable Markdown TypeScript/JavaScript snippets for disallowed Promise methods and unapproved Promise host seams. It makes the "Everything should be Effects" rule executable while allowing explicit platform Adapter seams such as Fetch handlers, Vite hooks, CLI/verify launch, Web Streams, comparison snippets, and Solid/React Suspense.
- **Public API Symbol Policy**: the workspace public-surface Module in `scripts/public-api-symbol-policy.mjs` that owns declaration-level LSP hover pins, explicit namespace-only alias mappings, and curated namespace-backed source-module allowances. The Public API Inventory Audit consumes it and rejects symbol policy files that are not reachable from a package export or re-exported public source Module, and rejects hover declarations that are not reachable as package Interface symbols or declared namespace aliases.
- **Start Virtual Declaration Artifact**: the copied declaration Adapter for `@sunfall/arc-start/virtual`. The source Interface lives in `packages/start/src/virtual-modules.d.ts`; the build copies it to `packages/start/dist/virtual.d.ts`, and the package dry-run gate compares those bytes while rejecting stale declaration maps.
- **UI Lifecycle Callback Seam**: the Core `UiScope` and `watch(...)` policy that invokes cleanup and watcher callbacks inside Effect through `EffectInputCallbackError` normalization, so pure callbacks are deferred until disposal and synchronous throws or defects do not escape lifecycle registration, signal notification, or later finalizer cleanup. Runtime-owned UI lifetimes use `makeRuntimeUiScope(...)` so late finalizers run on the owning Runtime Spine.
- **Runtime UI Scope Frame**: the Core lifecycle helper created by `makeRuntimeUiScopeFrame(...)`. It pairs a Runtime Spine with a `UiScope`, runs synchronous adapter construction with both runtime and scope ambient, and exposes runtime-bound disposal so React and Solid component/route lifetimes share one cleanup policy.
- **Core Definition Registry**: the Core Module that owns Action and Server function registration, lookup, snapshots, isolated registry adapters, duplicate policy diagnostics, and explicit app registry assembly so app graphs can be built from stable definition facts instead of live globals.
- **Server Wire Codec**: the Core Module that owns server-function schema encode/decode, RPC request/response envelope decoding, schema-presence manifest projection, and server defect/error serialization. The public `Server` facade delegates to this Module so local clients, mocks, and Start transports share one wire policy for inputs, outputs, and domain failures.
- **Action Submission Controller**: the Core Action Module that owns submission versioning, current fiber coordination, visible state transitions, invalidation-plan state, stale interruption, and reset interruption behind both `Action.use(...)` and Start's stateful `StartAction.use(...)`.
- **Action Runtime Binding**: the Core `Action.use(definition, { runtime })` Interface rule that an explicit typed Runtime Spine discharges the services it provides, including the Resource Store, and adds the runtime error channel to `submitEffect(...)` instead of leaving stale action requirements in LSP hovers.
- **Action Execution Workflow**: the internal Core Action Module in `packages/core/src/action-execution-workflow.ts` that runs one live `Action.use(...)` instance. It owns callback normalization, retry wrapping, optimistic transaction commit/rollback, stale-submission interruption, invalidation planning/execution through Resource Runtime, and visible submission state updates while `Action.use(...)` owns runtime binding and public type subtraction.
- **Action Optimistic Transaction**: the Core Action Module that owns optimistic signal patch stacking, commit, rollback, and cross-submission recomputation while `Action.use(...)` remains the Adapter that wires it into submission workflows.
- **Action Callback Policy**: the Core Action Module rule that `run`, `optimistic`, and `invalidates` callbacks are invoked through an Effect-visible error seam. Synchronous user callback throws become `EffectInputCallbackError` failures and action state failures instead of construction-time throws or defects.
- **Program Runtime Error Channel**: the Core Program rule that model/update/command/subscription failures stay in the Program error channel, while Runtime Spine provision or startup failures flow through a separate `ER` parameter on `Program.RuntimeError` and adapter hooks.
- **Program Contract**: the internal Core Module in `packages/core/src/program-contract.ts` that owns Program symbols, public data Interfaces, event DTOs, story Interfaces, and the runtime error channel. The public `program.ts` facade re-exports it so LSP hovers keep the stable `Program` surface while runtime/story/primitives Modules import the contract directly.
- **Program Tagged Handler Interface**: the public Core Program shorthand that accepts an exhaustive `on` handler map keyed by each tagged message `_tag`, pairs naturally with `Program.emit(...)` for immediate or Effect-produced follow-up messages, and normalizes to the ordinary Program update callback so the Foldkit-simple front door and the existing Effect runtime share one implementation path.
- **Program Primitives**: the internal Core Module in `packages/core/src/program-primitives.ts` that owns Program guards, tagged-handler update normalization, command/subscription normalization, failure DTO construction, EffectInput update stepping, and pure Program constructors. Story and Runtime consume this shared policy instead of duplicating step and failure normalization.
- **Program Story Harness**: the internal Core Module in `packages/core/src/program-story.ts` that owns deterministic story execution, command resolution, and story history state without importing runtime Queue, Fiber, Scope, or subscription machinery.
- **Program Runtime Coordinator**: the internal Core Module in `packages/core/src/program-runtime.ts` that owns live Program queue processing, command fibers, subscription fibers, runtime provision, failure recording, dispatch acknowledgements, subscription generations, and disposal. The public `program.ts` facade only captures the current Runtime Spine and `UiScope` before delegating to this coordinator.
- **Program Runtime Scheduler**: the internal Core Module in `packages/core/src/program-runtime-scheduler.ts` that owns Program background-fiber policy. Runtime-owned detached work enters the Runtime Spine through `runtime.runFork(...)`, while already-provided acknowledged processor/subscription Effects preserve typed Runtime Spine startup/provision failures in Program failure channels.
- **Program Runtime Timeline**: the internal Core Module in `packages/core/src/program-runtime-timeline.ts` that owns Program event retention, sequence assignment, optional program name annotation, disabled timeline behavior, and timeline clearing while `program.ts` keeps message queue, command fibers, subscriptions, failures, and public Program facades local.
- **Form Validation Runtime**: the Core form controller logic that snapshots values, tracks validation revisions, normalizes schema and validator callback failures into typed validation state, and only lets the latest validation commit form state while stale validations still return their captured Effect result.
- **Route Grammar**: the canonical path segment language shared by core Route matching/building and Start file-route manifests. It owns static segments, dynamic params, optional params, route-id slugs, segment ordering, and prefix checks.
- **Route Preload Requirement Surface**: the Core Route Interface rule that service requirements returned by `preload` stay on the route definition and flow through `Route.preloadEffect(...)`, `Route.planPreloadEffect(...)`, `Route.planNavigationEffect(...)`, Start request preload, and Effect-first host adapters; adapters may erase them only at an explicit Runtime boundary.
- **Route Lazy Component Descriptor**: the Core Route Module value created by `Route.lazyComponent(...)`. It accepts an Effect loader, exposes `preloadEffect()`, caches the detached load fiber, and throws tagged pending/failure values from `Route.readComponent(...)` so React and Solid own the final Suspense Promise token at their host Adapter seams.
- **Browser History Adapter**: the Core Browser Router Module seam that reads current hrefs, subscribes to external history changes, and commits programmatic navigation. Same-href programmatic commits are idempotent; React and Solid router Adapters project that policy into their host lifecycle, while Core owns window-history and memory implementations for shared tests.
- **Router Provider History Projection**: the React and Solid `RouterProvider` Adapter rule that forwards a supplied `BrowserHistoryAdapter` to the Core Browser Router Host Controller. Golden-path provider usage can therefore use memory, test, native, or custom host history without mutating `window.history`.
- **Browser Router Kernel**: the Core Browser Router Module in `packages/core/src/browser-router-kernel.ts` that owns route matching, navigation generations, active preload `UiScope` disposal, membership failures, stale preload suppression, and typed router state. Valid and invalid navigation paths both pass through this lifetime owner so React and Solid Adapters cannot inherit stale route commits from superseded preload work.
- **Browser Router Host Controller**: the Core Browser Router Module facade that binds a Browser Router Kernel to a Browser History Adapter. It owns idempotent start/dispose, Effect-first `disposeEffect()` teardown, initial navigation, external history listener wiring, programmatic commit forwarding, and route preload disposal while React and Solid own framework reactivity and component/owner cleanup.
- **Browser Router Initial Matched State Policy**: the Core Browser Router Module policy that chooses whether the initially matched route starts `Ready` or `Pending`. Server rendering and host hydration start ready to preserve existing DOM, while client-only browser mounts start pending so unresolved preloads can show pending UI. React passes an explicit `hydrating` fact, and Solid passes its owner hydration detection.
- **Browser Router Link Decision**: the Core Browser Router Module policy that maps RouterLink hover, click, and rendered-preload identity facts to adapter-neutral `Preload`, `Navigate`, `Ignore`, or stable preload-owner identities. It normalizes framework-absent download facts such as `false`, `null`, and `undefined` before deciding browser ownership. React and Solid pass user-handled event facts, target/download attributes, route membership, and resolved hrefs to this policy while keeping DOM event wiring local.
- **Browser Router Link Preloader**: the Core Browser Router Module in `packages/core/src/browser-router-link.ts` that owns hover preload fibers, stable preload identities, stale-target interruption, defect swallowing for fire-and-forget hover work, and awaitable `interruptEffect()` cleanup for router-owned links. React and Solid keep DOM event wiring local while delegating preload lifetime policy to this Module.
- **Browser Route Render Decision**: the Core Browser Router Module policy that maps `BrowserRouterState` to adapter-neutral outlet decisions: pending, failure, not-found, ready component props, or empty ready routes. React and Solid consume this shared decision while keeping component invocation, default fallback rendering, and `UiScope` lifetime at their Adapter seams.
- **Devtools Panels**: the typed inspection Module that projects summaries into stable app graph, route, resource, action, collection, request, diagnostics, and causal graph panels. It owns summary and serialization dependencies internally while the root devtools facade owns only public wiring.
- **Devtools Public Contract**: the public Devtools DTO and Interface Module in `packages/devtools/src/devtools-contract.ts`. It owns JSON-safe snapshots, serialization policy, invalidation plans, route plans, request traces, runtime events, Start app graph diagnostics, summaries, causal graphs, panels, panel UI options, store Interfaces, and panel boot contracts. The Devtools root re-exports this contract for app code while internal Devtools modules import it directly instead of depending on the root facade or serialization implementation.
- **Devtools Summary Contract**: the devtools facade Module that composes snapshots, app graph diagnostics, request traces, route plans, invalidation plans, runtime events, resource index facts, and causal graph facts into the public `DevtoolsSummary`.
- **Devtools Summary Input Normalization**: the devtools Module policy that resolves explicit summary input overrides against the snapshot, summarizes invalidations, route plans, request traces, runtime events, and resource indexes once, then feeds both `DevtoolsSummary` and the causal graph from the same prepared facts.
- **Devtools App Graph Summary**: the devtools Module that projects Start App Graph Diagnostics into route, server function, action, resource, collection, endpoint, module, and schema-coverage summary facts.
- **Devtools Summary Facts**: the devtools Module that normalizes invalidation plans, route plans, request traces, runtime events, and resource index facts into summary DTOs.
- **Devtools Causal Graph**: the devtools Module that turns app graph facts, runtime facts, invalidations, route plans, request traces, resources, and events into causal nodes and edges for panel UIs.
- **Devtools Route Plan Projection**: the devtools Module that turns a summarized route plan into causal graph route, route-plan, resource, match, preload, and hydration facts. Standalone route plans and request-embedded route plans use this same projection, while their callers add only source-specific edges.
- **Devtools Graph Identity**: the devtools Module that owns stable ids for causal graph nodes, causal graph edges, panel rows, runtime events, route plans, invalidations, and schema diagnostics so panels, summaries, and graph construction cannot drift when unrelated facts are inserted.
- **Devtools Fact Identity**: the devtools Store Module that preserves fact references when bounded histories trim old invalidation plans, route plans, or request traces arrive without ids. It rebases snapshot, runtime, and request-trace action invalidation indexes, route-plan indexes, fallback request trace ids, and duplicate runtime event sequence/tag pairs before summary or causal graph projection. Store and Summary fact matching share first-match index helpers backed by a stable fingerprint derived from the Devtools Serialization Policy.

## Architectural Commitments

- Resource families are definitions; live async/cache state belongs to the current Resource Store.
- Resource lifetimes should use Effect fibers, `Clock`, interruption, and scopes rather than host timers hidden inside implementations.
- Non-forced Resource prefetch is idempotent while a Resource ref is already fresh and live; hover, route preload, and UI binding adapters must be able to call prefetch without republishing lifecycle events or remounting UI.
- Effects should cross host seams through the Runtime Spine so services, request context, cancellation, retries, and the Resource Store stay together.
- Full-stack request work should use a Request Runtime so one SSR request cannot observe another request's resource entries, hydration payloads, tag graph, event stream, or lifetime fibers.
- A streamed Request Runtime closes when the streamed response body closes or is cancelled, not when the request handler first returns the `Response`.
- Promise boundaries are compatibility adapters for UI and host platform requirements only; canonical framework APIs stay Effect v4 and internals keep native Effect forms.
- Package source Promise seams should be enforced by `pnpm audit:effect-first` as part of `pnpm verify`, not by convention alone.
- Mutations invalidate domain facts through the Resource Dependency Graph, not route names, component trees, or ad hoc cache strings.
- Devtools and diagnostics should subscribe to Resource Event Stream and Collection Event Stream facts instead of coupling to Resource Store or Collection Store internals.
- Streaming should preserve native Effect `Stream` semantics until the final host adapter creates a Web `ReadableStream` or `Response`.
- Start manifests should be deterministic, Schema-branded at identifier fields, deserializable through typed Effect parsers, and validated before production bundling.
- Build and devtool checks should consume Start App Graph Diagnostics instead of ad hoc manifest JSON traversal.
- Generated virtual modules should call shared Start App Graph Diagnostics policy functions rather than embedding second implementations of policy checks.
- App construction should capture Core Definition Registry snapshots or accept explicit registry inputs so route/app graphs do not accidentally depend on later global registrations.
- Progressive action redirects and validation failures should be typed data, not untyped thrown control flow.
- Progressive form posts should use Start Action Requests so JS-enhanced and no-JS submissions execute the same Action Definition and services.
- Domain identifiers and generated framework identifiers should be Schema-branded types at API seams. Route params, resource inputs, server contracts, action inputs, and manifests should reject accidentally-compatible strings at compile time while still decoding cleanly at the wire.
- Public Effect error channels should never be `unknown`: infallible work uses `never`, fallible work uses concrete tagged errors or explicit error unions, and raw `unknown` stays inside payload/cause fields at host or wire boundaries.
