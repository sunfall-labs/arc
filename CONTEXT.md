# Sunfall Arc Context

## Domain Vocabulary

- **Runtime Spine**: the `SunfallArcRuntime<R, ER>` that owns Effect execution for an app, browser session, server request, or test. It carries the Effect `ManagedRuntime`, the Resource Store, and the services that app work depends on; its typed Interface only discharges services actually provided by `R`.
- **Erased Runtime Runner**: the `AnySunfallArcRuntime<ER>` Adapter Interface used at Solid contexts, platform adapters, and ambient host seams where the concrete app service set cannot be named. It is explicit erasure through `eraseRuntime(runtime)`, not a replacement for typed Runtime Spine APIs.
- **Request Runtime**: a per-request view of the app Runtime Spine with the same Effect services and a fresh Resource Store. Start uses it for SSR preload, render, and server RPC work.
- **Request Runtime Lifecycle Module**: the internal Start Module in `packages/start/src/request-runtime-lifecycle.ts` that runs a selected response Effect through response-context application, Request Runtime disposal, ending the request span, failure/interruption teardown, and streamed response finalization. The Start Request Handler owns endpoint/render selection; this Module owns lifecycle completion.
- **Resource Definition**: the stable `Resource.define(...)` descriptor. It names the resource, describes input/output/error schemas or types, and defines loading policy, but does not own live cache state.
- **Resource Store**: the runtime/request-scoped owner of live resource entries, Effect caches, known resource inputs, semantic tag index, hydration state, and resource lifetime fibers. This is the seam that keeps SSR requests, client runtimes, and tests isolated. Its public Interface exposes event bus, module registry, fiber registry, and diagnostics Modules; raw entry/input/cache maps remain internal implementation state.
- **Resource Runtime**: the Core Module that binds Resource Definitions to the active Resource Store. It owns runtime store lookup, touched-ref collection, in-flight fiber coordination, synchronous read state, invalidation execution, dehydration, and hydration behind the public Resource facade.
- **Resource Read Boundary**: the synchronous Core read Interface for already-loaded Resource refs. Missing or expired data throws typed `ResourcePending` and failed data throws `ResourceFailure`; UI adapters such as Solid own any host Suspense conversion they need to throw.
- **Async Result**: Effect's `AsyncResult` (`effect/reactivity`), Arc's single async-state vocabulary. Resource entries, Action submission state, and Live Query state are `AsyncResult` values held in Arc signals: loads mark the current tag `waiting`, `Success` carries a `Clock` timestamp, and `Failure` carries the full `Cause` plus `previousSuccess`.
- **Async Result Settlement**: the internal Core helper (`packages/core/src/async-result-settle.ts`) that settles every Resource load and Action submission from its `Exit` with `Clock` time inside an uninterruptible region. Typed errors, defects, and mixed causes settle to `Failure`; interrupt-only exits are cancellation and return to the prior settled result with `waiting: false`.
- **Resource Read Decision**: the Core Resource Runtime policy, derived from the entry's `AsyncResult`, that computes the read outcome for `Resource.read(...)`: value, typed pending (`ResourcePending` with reason `Initial`/`Pending`/`Collected`), typed failure (`ResourceFailure` carrying the settled `AsyncResult.Failure`), collected reset, and stale refresh. A `Failure` waiting on a retry reads stale data when present. Host seams (such as the Solid Suspense binding) run `Resource.read(...)` on their runtime instead of duplicating Resource Read Boundary rules.
- **Resource UI Binding Controller**: the Core Module in `packages/core/src/resource-ui-binding.ts` that owns adapter-neutral Resource UI policy: ref identity, runtime-bound refresh/preload Effects, automatic preload fibers, keyed preload failures, observer and host setter failure swallowing, stale preload interruption, retained-ref cleanup through `dispose()`, and Suspense preload-token dedupe. It consumes Resource Runtime functions directly instead of routing sibling implementation work through the public `Resource` facade. The Solid adapter keeps host reactivity and host Suspense throwing at its adapter seam.
- **Resource Suspense Preload Controller**: the Core Module in `packages/core/src/resource-ui-binding.ts` that dedupes host Suspense tokens per Resource ref, owns preload join fibers, observer removal, stale-ref interruption, and exposes `interrupt()`/`dispose()` Effects that adapters await, or fork from host cleanup hooks (forking starts synchronously).
- **Resource Rows**: the `rows` option of a Resource family whose output is an array (`key`, `indexes`, optional `changes`), implemented in core `resource-rows.ts`. Rows are derived from the entry's value: key positions and index buckets are built lazily per value array and cached by array identity; an update derives the new array's view from the old one (shared positions, only the changed buckets move); a reload is reconciled by key so unchanged rows keep their object identity.
- **Resource Row Patch**: an Action's `transaction.insert/update/delete(ref, key, ...)` on a ref of a Resource with `rows`. Each is an optimistic patch layer over the entry's synced value, exactly like `transaction.set`: reloads replace the value underneath, success folds it in, failure or interruption rolls it back and rebases other submissions' layers.
- **Resource Row Change Feed**: `rows.changes(input)`, a Stream of `Upsert`/`Update`/`Delete` batches started by an entry's first success on the active Resource Store's fibers. Batches apply to the synced value as a Timeline `change` commit; a failure stops the feed and publishes `ResourceRowsChangesFailure`.
- **Resource Persistence**: core `resource-persistence.ts`, behind `policy.persist: { key, version }`. It writes settled values (loads, hydration, change batches) to the runtime's `KeyValueStore` under `arc/resources/v<version>/<key>/<ref key>`, encoded like a hydration snapshot, and restores a never-loaded entry before reloading it in the background. `policy.persist` adds `KeyValueStore` to the family's `R`, which Start provides (client Layer's or `localStorage` in the browser, a keep-nothing store in request runtimes); failures are logged.
- **Indexed Join Plan**: a Query plan step that joins through the scalar or multi-value buckets of a source Resource's `rows.indexes` instead of scanning the joined rows for each left-side row.
- **Query Source Adapter**: the internal DB Adapter Module in `packages/db/src/query-source-adapter.ts` that presents refs of Resources with `rows` to Query Builder, Query Plan, Live Query State, and Live Query Runtime through one query-readable Interface: the entry's visible rows (optimistic patches included) read from the query's Resource Store, their keys, index buckets, load result, and preload/refresh Effects.
- **Query Stage Plan**: the internal DB Query Module Interface compiled from a fluent Query Builder. It owns source roles, unique source adapters, base-source ordering, identity alias ordering, join sources, grouping, filters, ordering, and window facts so snapshot execution, projection, preload/refresh, Live Query State, and Live Query Runtime share one stage plan instead of re-deciding stage policy separately.
- **Query Execution Plan Module**: the internal DB Module in `packages/db/src/query-execution-plan.ts` that owns Query validation entrypoints, source alias validation, source adapter selection, source preload/refresh, snapshot execution, diagnostics, stable equal-order tie-break identity, and remaining projection stages after live-query IVM has already applied filters, grouping, ordering, or windows. Query Builder stays the immutable DSL while Query once/live/diagnostics callers consume this Module.
- **Query Context Identity**: the internal DB Module in `packages/db/src/query-context-identity.ts` that owns source alias/key identity, merged context identity, ordered-context tie-break identity, IVM context metadata, and source row delta identity shared by Query Execution Plan and Live Query Runtime.
- **Query Plan Diagnostics**: an inspectable summary of a Query plan's sources, joins, join strategy, row counts, and estimated comparison cost. It gives devtools leverage without exposing Query Builder internals.
- **Query Builder Module**: the DB Module that owns the immutable Query DSL, aggregate helpers, one-shot query facades, live query creation, and query diagnostics facades behind the public DB root facade. The `Query.*` namespace is the preferred public Interface; top-level Query type mirrors remain expert-public compatibility pins and should track the namespace vocabulary.
- **Live Query Runtime**: the DB Module that owns incremental IVM graph construction, source synchronization, joins, grouping, ordering, windowing, and output multiplicity for reactive queries while delegating query-stage projection policy to the Query Execution Plan Module.
- **Live Query State**: the DB Module that adapts Live Query Runtime evaluation into the public `LiveQuery` handle, owning last-good data retention, evaluation failures, and folding the source Resources' `AsyncResult` load state into one `AsyncResult<ReadonlyArray<T>, E>` (`Failure` keeps the last good rows as `previousSuccess`). Mutable engine/evaluation facts are keyed by the active Resource Store, not by the Live Query descriptor, so SSR requests, browser runtimes, and tests do not share derived query state.
- **Resource Snapshot Codec**: the Core Module that validates, clones, encodes, decodes, and applies Resource hydration snapshots before they cross SSR, persistence, or adapter seams. A snapshot keeps Arc's `name`/`key`/`input` envelope and stores `state` as the `AsyncResult.Schema`-style JSON of a settled `Success` (`{ _tag, value, waiting: false, timestamp }`); hydration is Success-only. Invalid payloads fail with typed `Resource.SnapshotCodecError` or `Resource.HydrationApplyError` values instead of raw decode failures.
- **Stable Identity Codec**: the Core stable identity Module used by query, live-query, and diagnostic fingerprints. It has structured encodings for JSON-compatible data, Date, URL, Map, Set, binary values, undefined, sparse array holes, marker-shaped plain objects, and typed failures for unsupported values.
- **Resource Lifetime**: the Effect-native lifecycle of a resource entry, including pending refresh interruption, cache invalidation, GC sleep fibers, and deletion.
- **Resource Event Stream**: the Resource Store's Effect `PubSub` of lifecycle facts, used by tests and future devtools to observe resource behavior without reading private maps.
- **Resource Dependency Graph**: the Resource Store's mapping from semantic `Resource.tag(...)` values to the live resource refs that most recently provided those facts.
- **Resource Load Error**: the public Resource error channel for load state,
  status, and preload/refresh Effects: exactly the Resource's declared load
  error. A `load` or `provides` callback that breaks its contract is a defect
  carrying `EffectInputCallbackError`, never a typed failure.
- **Signal Dependency Tracker**: the Core Module that records signal dependencies while `watch(...)` callbacks and `Signal.derive(...)` computations run. It owns source de-duping, subscription cleanup, and queued recompute behavior.
- **EffectInput Promise Guard**: the Core Module policy that rejects Promise-shaped values, including union success values with Promise-like members, crossing `EffectInput` seams at the public type surface and at runtime. Host Promise work must be adapted through `Effect.tryPromise(...)`, while internal Action, Resource, Server, Form, Query, and Start callbacks stay Effect-first.
- **Effect-first Source Audit**: the workspace verification script that scans package source, workspace scripts, public type tests, generated starter templates, and copyable Markdown TypeScript/JavaScript snippets for disallowed Promise methods and unapproved Promise host seams. It makes the "Everything should be Effects" rule executable while allowing explicit platform Adapter seams such as Fetch handlers, Vite hooks, CLI/verify launch, Web Streams, comparison snippets, and Solid Suspense.
- **Public API Symbol Policy**: the workspace public-surface Module in `scripts/public-api-symbol-policy.mjs` that owns declaration-level LSP hover pins, explicit namespace-only alias mappings, and curated namespace-backed source-module allowances. The Public API Inventory Audit consumes it and rejects symbol policy files that are not reachable from a package export or re-exported public source Module, and rejects hover declarations that are not reachable as package Interface symbols or declared namespace aliases.
- **Start Virtual Declaration Artifact**: the copied declaration Adapter for `@sunfall/arc-start/virtual`. The source Interface lives in `packages/start/src/virtual-modules.d.ts`; the build copies it to `packages/start/dist/virtual.d.ts`, and the package dry-run gate compares those bytes while rejecting stale declaration maps.
- **UI Lifecycle Callback Seam**: the Core `UiScope` and `watch(...)` policy that invokes cleanup and watcher callbacks inside Effect through `EffectInputCallbackError` normalization, so pure callbacks are deferred until disposal and synchronous throws or defects do not escape lifecycle registration, signal notification, or later finalizer cleanup. Runtime-owned UI lifetimes use `makeRuntimeUiScope(...)` so late finalizers run on the owning Runtime Spine.
- **Runtime UI Scope Frame**: the Core lifecycle helper created by `makeRuntimeUiScopeFrame(...)`. It pairs a Runtime Spine with a `UiScope`, runs synchronous adapter construction with both runtime and scope ambient, and exposes runtime-bound disposal so Solid component/route lifetimes share one cleanup policy.
- **Core Definition Registry**: the Core Module that owns Action and Server function registration, lookup, snapshots, isolated registry adapters, duplicate policy diagnostics, and explicit app registry assembly so app graphs can be built from stable definition facts instead of live globals.
- **Server Function Rpc**: every `Server.contract` is an `effect/rpc` `Rpc` named after the function, built from required `input`/`output` schemas (`error` defaults to `Schema.Never`). Start serves the served functions as an `RpcGroup` through `RpcServer.toHttpEffect` (JSON serialization) and calls them from the browser with `RpcClient` over `HttpClient`; mocks and the in-process SSR client round-trip values through the same Rpc JSON codecs.
- **Action Submission Controller**: the Core Action Module that owns submission versioning, current fiber coordination, visible state transitions, invalidation-plan state, stale interruption, and reset interruption behind every Action instance (`Action.use(...)` and Solid's `Component.action(...)`), whether it submits locally or through an `ActionTransport`.
- **Action Runtime Binding**: the Core `Action.use(definition, { runtime })` Interface rule that an explicit typed Runtime Spine discharges the services it provides, including the Resource Store, and adds the runtime error channel to `submit(...)` instead of leaving stale action requirements in LSP hovers.
- **Action Execution Workflow**: the internal Core Action Module in `packages/core/src/action-execution-workflow.ts` that runs one live `Action.use(...)` instance. It owns callback normalization, retry wrapping, optimistic transaction commit/rollback, stale-submission interruption, invalidation planning/execution through Resource Runtime, and visible submission state updates while `Action.use(...)` owns runtime binding and public type subtraction.
- **Action Optimistic Transaction**: the Core Action Module that owns one submission's optimistic patches: Signal and Resource entry patch stacking (`set`, and Resource Row Patches through `insert`/`update`/`delete`), committed or rolled back together, with cross-submission recomputation, while `Action.use(...)` remains the Adapter that wires it into submission workflows.
- **Action Callback Policy**: the Core Action Module rule that `run`, `optimistic`, and `invalidates` callbacks are invoked through an Effect seam where breaking the callback contract (a synchronous throw, a Promise-shaped return, an optimistic row update that changes its key) is a defect carrying `EffectInputCallbackError`, so submissions fail only with the Action's declared error and transport failures.
- **State**: the one writable client state: a named model (`State.define({ name, initial, on })`) that changes only through its tagged messages. Public Signals are read-only; writable signals (`SignalWrites`) are internal to the framework, so every change is a State message, an Action, or a framework event.
- **App State**: a State whose definition says `scope: "app"`: the runtime owns its one instance (registered on the runtime's Resource Store by `appStateOnRuntime` in `packages/core/src/state-start.ts` and disposed with it), so every `Component.state` binding shares it and each Start request runtime has its own. The default scope, `"component"`, gives each binding Component instance its own.
- **State Runtime Error Channel**: the Core State rule that handler/command/subscription failures stay in the State error channel, while Runtime Spine provision or startup failures flow through a separate `ER` parameter on `State.RuntimeError` and adapter hooks.
- **State Contract**: the internal Core Module in `packages/core/src/state-contract.ts` that owns State symbols (including `StateRefTypeId`, which carries a running State's model cell for Action optimistic patches), public data Interfaces, and the runtime error channel. The public `state.ts` facade re-exports it so LSP hovers keep the stable `State` surface while runtime/primitives Modules import the contract directly.
- **State Tagged Handler Interface**: the one way to write State transitions: an exhaustive `on` handler map keyed by each tagged message `_tag` (PascalCase), whose handlers are pure and synchronous (the next model, or `State.next(model, commands)`), paired with `State.emit(...)`, the one command constructor (an immediate message, the message an Effect produces, or nothing for a `void` Effect). The message union is inferred from `on`, or named up front with `State.define<Model, Message>()` when commands emit the State's own messages.
- **State Primitives**: the internal Core Module in `packages/core/src/state-primitives.ts` that owns State guards, `State.define` inference, the pure `State.step` (handler dispatch by `_tag` plus model validation), command/subscription normalization, failure DTO construction, and pure State constructors. Tests call `State.step` directly and the Runtime runs the same function, so there is one transition path.
- **State Runtime Coordinator**: the internal Core Module in `packages/core/src/state-runtime.ts` that owns live State queue processing, command fibers, subscription fibers, runtime provision, failure recording, dispatch acknowledgements, subscription generations, and disposal. Messages apply to the model's optimistic base (`signal-optimistic-layer.ts`), so in-flight Action patches re-apply over them.
- **State Runtime Scheduler**: the internal Core Module in `packages/core/src/state-runtime-scheduler.ts` that owns State background-fiber policy. Runtime-owned detached work enters the Runtime Spine through `runtime.runFork(...)`, while already-provided acknowledged processor/subscription Effects preserve typed Runtime Spine startup/provision failures in State failure channels.
- **Timeline**: the public Core Module in `packages/core/src/timeline.ts` that records every committed signal change set through the commit recorder seam in `signal-transaction.ts`, labels entries with transaction causes, and renders a travelled view without rewriting committed state. Every entry has a cause, because every write happens inside a **Named Transition**.
- **Named Transition**: the name every framework signal write commits under. A write joins the caller's transaction (whose cause names it: a State message, an Action event, a Resource or router event) or commits under the fiber's ambient transition (`withSignalTransition`, provided by `Component.callback(name, f)` as `<Component>.<name>` and `Component.stream`). A write with neither is an internal assertion (`SignalWriteOutsideTransition`); application code cannot reach it because public Signals are read-only. Framework bookkeeping derived from recorded state (a recording's own state, a router outlet's node) writes through `writeUntracedSignals` and is never recorded. States keep no timeline of their own; a State's history is the Timeline filtered to its model signal.
- **Form Validation Runtime**: the Core form controller logic that snapshots values, tracks validation revisions, normalizes schema and validator callback failures into typed validation state, and only lets the latest validation commit form state while stale validations still return their captured Effect result.
- **Route Grammar**: the canonical path segment language shared by core Route matching/building and Start file-route manifests. It owns static segments, dynamic params, optional params, route-id slugs, segment ordering, and prefix checks.
- **Route Preload Requirement Surface**: the Core Route Interface rule that service requirements returned by `preload` stay on the route definition and flow through `Route.preload(...)`, `Route.planPreload(...)`, `Route.planNavigation(...)`, Start request preload, and Effect-first host adapters; adapters may erase them only at an explicit Runtime boundary.
- **Route Lazy Component Descriptor**: the Core Route Module value created by `Route.lazyComponent(...)`. It accepts an Effect loader, exposes `preload()`, caches the detached load fiber, and throws tagged pending/failure values from `Route.readComponent(...)` so the Solid adapter owns the final Suspense Promise token at its host Adapter seam.
- **Browser History Adapter**: the Core Browser Router Module seam that reads current hrefs, subscribes to external history changes, and commits programmatic navigation. Same-href programmatic commits are idempotent; the Solid router Adapter projects that policy into its host lifecycle, while Core owns window-history and memory implementations for shared tests.
- **Router Provider History Projection**: the Solid `RouterProvider` Adapter rule that forwards a supplied `BrowserHistoryAdapter` to the Core Browser Router Host Controller. Golden-path provider usage can therefore use memory, test, native, or custom host history without mutating `window.history`.
- **Browser Router Kernel**: the Core Browser Router Module in `packages/core/src/browser-router-kernel.ts` that owns route matching, navigation generations, active preload `UiScope` disposal, membership failures, stale preload suppression, and typed router state. Valid and invalid navigation paths both pass through this lifetime owner so the Solid Adapter cannot inherit stale route commits from superseded preload work.
- **Browser Router Host Controller**: the Core Browser Router Module facade that binds a Browser Router Kernel to a Browser History Adapter. It owns idempotent start/dispose, Effect-first `dispose()` teardown, initial navigation, external history listener wiring, programmatic commit forwarding, and route preload disposal while the Solid adapter owns framework reactivity and component/owner cleanup.
- **Browser Router Initial Matched State Policy**: the Core Browser Router Module policy that chooses whether the initially matched route starts `Ready` or `Pending`. Server rendering and host hydration start ready to preserve existing DOM, while client-only browser mounts start pending so unresolved preloads can show pending UI. Solid passes its owner hydration detection.
- **Browser Router Link Decision**: the Core Browser Router Module policy that maps RouterLink hover, click, and rendered-preload identity facts to adapter-neutral `Preload`, `Navigate`, `Ignore`, or stable preload-owner identities. It normalizes framework-absent download facts such as `false`, `null`, and `undefined` before deciding browser ownership. The Solid adapter passes user-handled event facts, target/download attributes, route membership, and resolved hrefs to this policy while keeping DOM event wiring local.
- **Browser Router Link Preloader**: the Core Browser Router Module in `packages/core/src/browser-router-link.ts` that owns hover preload fibers, stable preload identities, stale-target interruption, defect swallowing for fire-and-forget hover work, and awaitable `interrupt()` cleanup for router-owned links. The Solid adapter keeps DOM event wiring local while delegating preload lifetime policy to this Module.
- **Browser Route Render Decision**: the Core Browser Router Module policy that maps `BrowserRouterState` to adapter-neutral outlet decisions: pending, failure, not-found, ready component props, or empty ready routes. The Solid adapter consumes this shared decision while keeping component invocation, default fallback rendering, and `UiScope` lifetime at its Adapter seam.
- **Devtools Panels**: the typed inspection Module that projects summaries into stable route, resource, action, request, diagnostics, and causal graph panels. It owns summary and serialization dependencies internally while the root devtools facade owns only public wiring.
- **Devtools Public Contract**: the public Devtools DTO and Interface Module in `packages/devtools/src/devtools-contract.ts`. It owns JSON-safe snapshots, serialization policy, invalidation plans, route plans, ended Effect spans, runtime events, summaries, causal graphs, panels, panel UI options, store Interfaces, and panel boot contracts. The `Devtools` namespace names its public types for app code while internal Devtools modules import it directly instead of depending on the root facade or serialization implementation.
- **Devtools Summary Contract**: the devtools facade Module that composes snapshots, spans, route plans, invalidation plans, runtime events, resource index facts, and causal graph facts into the public `Devtools.Summary`.
- **Devtools Summary Input Normalization**: the devtools Module policy that resolves explicit summary input overrides against the snapshot, summarizes invalidations, route plans, request spans, runtime events, and resource indexes once, then feeds both `Devtools.Summary` and the causal graph from the same prepared facts.
- **Devtools Summary Facts**: the devtools Module that normalizes invalidation plans, route plans, request spans, runtime events, and resource index facts into summary DTOs.
- **Devtools Causal Graph**: the devtools Module that turns runtime facts, invalidations, route plans, resources, and events into causal nodes and edges for panel UIs.
- **Devtools Route Plan Projection**: the devtools Module that turns a summarized route plan into causal graph route, route-plan, resource, match, preload, and hydration facts. Standalone route plans and request-embedded route plans use this same projection, while their callers add only source-specific edges.
- **Devtools Graph Identity**: the devtools Module that owns stable ids for causal graph nodes, causal graph edges, panel rows, runtime events, route plans, invalidations, and schema diagnostics so panels, summaries, and graph construction cannot drift when unrelated facts are inserted.
- **Devtools Fact Identity**: the devtools Store Module that preserves fact references when bounded histories trim old invalidation plans or route plans. It rebases snapshot and runtime action invalidation indexes, route-plan indexes, and duplicate runtime event sequence/tag pairs before summary or causal graph projection. Store and Summary fact matching share first-match index helpers backed by a stable fingerprint derived from the Devtools Serialization Policy.
- **Devtools Serialization Policy**: the devtools Module that turns arbitrary runtime values into bounded, JSON-safe inspection values with depth, entry, string, accessor, circular-reference, Map, Set, Error, and object-copy handling.
- **Devtools Store Snapshot Detachment**: the devtools Store Module policy that copies snapshots, route plans, spans, invalidation plans, and runtime events at record/read seams so caller-owned objects cannot mutate recorded facts.
- **Devtools Panel Contract**: the devtools Module that owns panel ids, severities, finite-number and plain-record JSON-safe item guards, trap-safe panel guards, overflow item identity, and inspected-window bridge payload normalization. A valid bridge payload contains the complete public panel catalog exactly once; normalization detaches DTOs and orders panels by the shared catalog instead of trusting host order. Renderers, browser extensions, app shells, tests, and agents consume this shared Interface instead of duplicating panel validation.
- **Devtools Panel Renderer**: the devtools Module that renders a `Devtools.Panels` model to deterministic HTML and owns DOM mount/update/unmount lifecycle helpers behind the public devtools root facade.
- **Project Demo Store**: the Project Console server-only Effect service in `examples/project-console/src/domain.server.ts` that owns seeded demo project state behind a Runtime Spine-provided `Ref`. Server functions depend on this store instead of module-global state, while `server.tsx` composes the store layer with `ProjectApiLive` only for the server app runtime so browser bundles stay seed-data-free.
- **Starter Catalog Manifest**: the workspace script Module in `scripts/starter-catalog.mjs` that owns copyable starter ids, source package names, generated package names, source/output directories, generated Vite/tsconfig/README content, source-package payload policy, and generated route/virtual artifact declarations. Starter packaging, package dry-runs, generated artifact drift checks, and Effect-first virtual template audits consume this catalog instead of duplicating starter identity facts.
- **Effect Script Command Runner**: the workspace script Adapter in `scripts/effect-command-runner.mjs` that builds Effect v4 `ChildProcess.Command` values and runs them through the local Node host. Release scripts use this runner for command cancellation, stdout/stderr capture, signal-aware failures, and one typed `ScriptCommandError` boundary instead of duplicating child-process callback plumbing.
- **Workspace Verification Plan**: the script Module in `scripts/workspace-verification-plan.mjs` that discovers package-level `verify` targets from workspace manifests. Both parallel `pnpm verify` and serial `pnpm verify:serial` consume this plan through `scripts/verify.mjs`, so new package-local verify scripts cannot drift between command lanes.
- **Project Console Starter Manifest Gate**: the Effect-first packaging policy in `scripts/package-project-console-starter.mjs` that compares the generated starter file manifest against the copyable source manifest, rejects forbidden build/dependency paths, rewrites workspace protocol dependencies to generated `.sunfall-arc-packages/*` local file adapters, and validates those local package payloads with the shared dist/declaration artifact policy used by package dry-runs.
- **Navigation Plan**: the typed route preload result that records the matched route, touched resource refs, and hydration payload for a URL.
- **Effect service**: a named `Context.Service` that represents app behavior behind a dependency-injection seam, such as `ProjectApi`, provided by a `Layer` per host or test. Arc adds no wrapper over it.
- **Streaming Response**: an Effect Stream of HTML, bytes, and hydration chunks that can be adapted to a Web `Response` at the host seam. The Start streaming Module also owns generic Web response body finalization so Runtime lifecycle code can observe close/error/cancel events without owning `ReadableStream` mechanics.
- **Start Hydration Payload**: the serializable Start payload that restores Resource state (rows included, as part of each value) into the browser Runtime Spine.
- **Start Hydration Transport**: the Start module that serializes, emits, reads, and applies Start Hydration Payloads for initial document scripts and streamed hydration chunks. Its parse, decode, encode, and read implementation is Effect-first; synchronous helpers are host-boundary facades that unwrap the same typed transport failures.
- **Start Manifest Wall**: the Start Module (`start-manifest-wall.ts`) that owns plugin options, file-route discovery, and the file-route manifest. File-route manifests are deterministic and validated (duplicate paths, ids, and support modules; malformed params) before bundling.
- **Generated Route Definitions Artifact**: the written `routeTree.gen.ts` surface that turns the Start file-route manifest into app-specific literal route ids, the `routeById` definition map, id-keyed params/search/href option maps, and LSP hoverable route types (routes are addressed by definition; `Route.isMatch(route, match)` narrows a match). The Vite virtual route module stays broad because it must type-check before app-specific generation exists.
- **Generated Route Definitions File Writer**: the Start Vite helper that plans and writes `routeTree.gen.ts`. It exposes an Effect-first writer with typed generation and filesystem errors for CI/agent diagnostics and keeps the synchronous writer as the Vite host hook boundary.
- **Start Action Request Codec**: the Start Module in `packages/start/src/start-action-request-codec.ts` that owns the Schema-backed JSON action request, schema-backed input encoding, progressive form hidden fields, synchronous form encode errors, and server JSON/form request decoding.
- **Start Action Response Codec**: the Start Module in `packages/start/src/start-action-response-codec.ts` that owns the action response wire contract as one Effect Schema tagged union (`Success`, `ValidationFailure`, `Redirect`, `Failure`, `ServerError`, `Defect`, with optional invalidation/hydration metadata), JSON/redirect response mode selection, action Exit-to-Response encoding, client response parsing, typed output/error decoding, and applying accepted response metadata in the submitting runtime: it hydrates returned resources, resolves Tag and Ref invalidation targets against registered Resource Definitions, filters hydrated refs out of refresh work, and maps malformed metadata to `ActionTransportError`.
- **Start Abort Signal Lifecycle Module**: the internal Start Module in `packages/start/src/start-abort-lifecycle.ts` that owns abort signal merging, fallback listener cleanup, abort reason propagation, scoped abort finalizers, and host-fiber interruption. Fetch host facades, Vite dev SSR readers, and Node/Vite callback Adapters consume this Module instead of duplicating abort listener policy.
- **Start Transport Endpoint Envelope**: the per-request Start transport Module policy that resolves a shared request id, transport kind, trace propagation headers, media diagnostics, and response diagnostic headers before RPC/action protocol handling. The request span and transport diagnostics consume the same envelope so generated ids cannot drift.
- **Start Transport Endpoint Runner**: the internal Start Module in `packages/start/src/start-transport-endpoint-runner.ts` that runs RPC and action endpoint work through one transport endpoint policy: envelope creation, request validation, Request Runtime provisioning, diagnostics headers, transport failure tracing, and runtime failure tracing. The RPC endpoint hands the request to `RpcServer`; the action endpoint provides its own decode, invocation, not-found, and response encoding.
- **Start Action Status Policy**: the Start action client rule set for mapping parsed action bodies to HTTP status expectations. Action `Success`/`Failure`/JSON `Redirect` require ok statuses, `ValidationFailure` requires HTTP 422, and `ServerError`/`Defect` bodies become `ActionProtocolError`/`ActionNotFound` or `ActionTransportError` with their transport status for diagnostics.
- **Start/Devtools Invalidation Structural Contract**: the deliberate DTO compatibility between `StartAction.InvalidationPlan` and `Devtools.InvalidationPlan`. Start owns the transport payload, Devtools owns the inspection payload, and type tests pin structural assignability so neither package depends on the other.
- **Start RPC Client**: the Start client Layer (`rpcClientLayer`) that provides `Server.Client` as an `effect/rpc` `RpcClient` over the runtime's `HttpClient` with JSON serialization, posting to `/__sunfall-arc/rpc`. Each server function gets a one-Rpc client the first time it is called, all sharing one HTTP protocol, because functions load as routes do.
- **Start Action Client**: the Start Module that keeps progressive (no-JS) form support for Actions (`StartAction.form`, `StartAction.decodeFormData`).
- **Action Transport**: Core's `ActionTransport` service, the Action counterpart of `Server.Client`. Every Action instance looks it up on submit; Actions it serves run remotely and their response (outcome, hydration, invalidations) applies to the submitting runtime, every other Action runs locally. Start's `App.launch(app)` provides it for the app's `actions`, so UI code has one way to submit.
- **Start Client HttpClient**: the browser's one `HttpClient`, shared by the Start RPC Client and the action transport: the client Layer's when it provides one (headers, retries, custom fetch), else `FetchHttpClient`. Trace propagation (`traceparent`) comes from `HttpClient`.

- **Start File Route Discovery**: the Start Manifest Wall Module that discovers route modules under a route directory as a typed Effect, with a synchronous facade only for Vite hooks and other sync host boundaries.
- **Start Request Handler**: the Start Module that owns server request endpoint selection, Request Runtime creation and provisioning, SSR preload/render orchestration, ResponseContext application, request span attributes, and stream/request finalization behind the public handler facade.

- **Request Runtime Finalization Event**: the Start Request Runtime completion state emitted for both buffered and streamed responses. It carries status, teardown reason, disposal snapshots, completion time, and optional stream facts so ending the request span has one finalization Interface.

## Architectural Commitments

- Resource families are definitions; live async/cache state belongs to the current Resource Store.
- Resource lifetimes should use Effect fibers, `Clock`, interruption, and scopes rather than host timers hidden inside implementations.
- Non-forced Resource preload is idempotent while a Resource ref is already fresh and live; hover, route preload, and UI binding adapters must be able to call preload without republishing lifecycle events or remounting UI.
- Effects should cross host seams through the Runtime Spine so services, request context, cancellation, retries, and the Resource Store stay together.
- Full-stack request work should use a Request Runtime so one SSR request cannot observe another request's resource entries, hydration payloads, tag graph, event stream, or lifetime fibers.
- A streamed Request Runtime closes when the streamed response body closes or is cancelled, not when the request handler first returns the `Response`.
- Promise boundaries are compatibility adapters for UI and host platform requirements only; canonical framework APIs stay Effect v4 and internals keep native Effect forms.
- Package source Promise seams should be enforced by `pnpm audit:effect-first` as part of `pnpm verify`, not by convention alone.
- Mutations invalidate domain facts through the Resource Dependency Graph, not route names, component trees, or ad hoc cache strings.
- Devtools and diagnostics should subscribe to Resource Event Stream facts instead of coupling to Resource Store internals.
- Streaming should preserve native Effect `Stream` semantics until the final host adapter creates a Web `ReadableStream` or `Response`.
- Start file-route manifests should be deterministic and validated before production bundling.
- App construction should capture Core Definition Registry snapshots or accept explicit registry inputs so route/app graphs do not accidentally depend on later global registrations.
- Progressive action redirects and validation failures should be typed data, not untyped thrown control flow.
- Progressive form posts should use Start Action Requests so JS-enhanced and no-JS submissions execute the same Action Definition and services.
- Domain identifiers and generated framework identifiers should be Schema-branded types at API seams. Route params, resource inputs, server contracts, action inputs, and manifests should reject accidentally-compatible strings at compile time while still decoding cleanly at the wire.
- Public Effect error channels should never be `unknown`: infallible work uses `never`, fallible work uses concrete tagged errors or explicit error unions, and raw `unknown` stays inside payload/cause fields at host or wire boundaries.
